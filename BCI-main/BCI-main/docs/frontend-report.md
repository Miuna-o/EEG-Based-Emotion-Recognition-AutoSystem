## 交付内容

工作台使用真实任务与评估记录，真实数据和模拟演示分别统计；无响应时使用“—”或加载状态。四步导入支持拖放与文件选择、明确的 real/demo 模式、元信息版本核对、实际数值预览及草稿提交保护。任务详情显示实际状态、处理日志、版本、取消与重试操作，并可在页面重载后恢复。

结果按样本展示分类输出，置信度和可靠性分列；δ、θ、α、β、γ 固定顺序展示可用证据和缺失原因。复核保留修订历史，报告由实际 API 生成。结果和报告发生版本过期时，页面显示过期状态并禁用普通导出；历史 ZIP 通过明确的独立操作下载。记录页支持编码、日期、状态筛选。设置帮助显示实际能力和有效配置，文字助手独立可选，研究工具展示现有桌面研究入口。

界面使用水波 SVG 品牌、白色卡片、背景 `#F5F8F8`、正文 `#172B3A`、辅助文字 `#526674`、主绿 `#0F766E` 与蓝 `#3B6EA8`。侧栏 224–240 px，可收起为 84 px；窄视口初始收起。原生按钮、标签、键盘焦点、跳转到主要内容及原生 dialog 支持可访问操作。

## 依赖与契约

实际运行 Node.js 22.14.0、React/React DOM 19.2.6、Vite 8.0.15、TypeScript 5.9.3、ECharts 6.1.0、Playwright 1.58.2、axe-core/playwright 4.11.1。版本锁定于 `package-lock.json`。TypeScript 采用 5.9.3，以满足当前 typescript-eslint 8.56.1 的版本范围。

`scripts/generate_types.py` 从真实 `backend.app.main.create_app().openapi()` 生成 `src/generated/openapi.json` 和 17 个 TypeScript schema 类型。包括数据集、任务、评估、复核、报告过期字段与助手请求。未声明响应模型的服务端返回形状单独记录于 `src/api.ts`，依据实际 routes/providers/preview 实现定义。

采用一个明确的查询 hook，按 API 路径及数据版本区分查询，使用 AbortController 中止旧请求并避免迟到覆盖。请求期间禁用重复操作，任务及复核使用幂等键，版本冲突错误显示服务端请求编号并允许读取最新版本。

## 已知限制

- 服务端当前没有 PACER 推理实现、训练权重和固定标签映射，真实模型 `available=false`；真实任务提交因此禁用。
- 固定模拟输出没有真实情绪推理意义。可靠性、频带证据和电极坐标以服务端缺失状态呈现。
- 预处理、特征提取、统计分析、分类训练与通用图表保留在桌面研究工具，尚未迁移至 Web。
- 助手实际模型的回答质量与本机外部服务连接尚需独立验证；本次验证默认未启用状态及测试 HTTP 替身下的客户端竞态和历史边界。
- 本次浏览器运行于本机已有 Chromium；可通过 `XINLAN_CHROMIUM` 指定其他可执行文件，否则使用 Playwright 默认安装。
- 验证产生的演示样本、匿名 CSV 草稿与复核报告保留于本地服务的 `.xinlan-data`；记录可识别为演示或测试编码。

复现命令与启动方式见 `frontend/README.md`。构建后重启本地服务，以加载 FastAPI 的静态资源挂载。

## 2026-11-15 频带输入审查修复

审查发现输入类型下拉框将 `band_features` 错误映射为 `FEATURES` 模态，而后端要求频带脑电输入明确为 `EEG`。先以实际服务和固定 `[2, 2, 5]` 三维合成频带数据复现保存后模态错误，再将映射修正为 `eeg/band_features → EEG`、`features → FEATURES`。

新增 `tests/band-metadata.spec.ts`，明确声明 sample/channel/band 轴、128 Hz、F3/F4、五频带、uV² 单位、样本编码与模拟标签空间。UI 重新选择频带类型并保存后，验证响应的模态为 `EEG`、shape 为 `[2, 2, 5]`、校验错误为空且状态为 `ready`。定向测试 1 项通过，8.0 秒；typecheck、lint、build 均通过。验证仅保存合成输入元信息，未提交模型分析任务。

## 2026-11-15 列表与版本绑定审查修复

先运行七项回归并观察预期失败，确认以下四类问题后修复：

1. 列表字段每次键入立即解析并回写，导致逗号被吞、名称拼接。现改为自由文本草稿，支持逗号与换行，仅在保存时按用户顺序解析。PATCH 仅提交相对初始元信息实际变化的字段，避免自动重传旧 labels；样本或特征映射变化后，由服务端撤销失效标签。
2. 历史记录曾使用最新数据 head 的编码。现以最新 OpenAPI 中 Job/Assessment/Report 的绑定版本 `display_code` 展示和检索，工作台也使用同一字段；编码缺失时显示内部编号。
3. 已打开的 JSON 报告曾在版本变更后继续显示。预览现保留 report_id、dataset_version、review_revision，独立轮询具体报告；发现来源或复核修订过期即关闭，并显示历史存档提示。
4. 提交幂等键曾贯穿整个导入组件生命周期。现绑定数据 ID、版本和 data_mode；同输入响应失败重试保留，新版本或新文件重新生成。

新增 `metadata-text.spec.ts` 两项逐字符输入回归，使用 `pressSequentially` 核对 `channel,` 与 `channel,time`、换行通道、频带、样本编码、标签空间和特征名称，保存后核对真实 API 数组与旧标签撤销。新增 `version-bindings.spec.ts` 三项，验证历史编码检索、结果页来源版本变更和记录页复核修订变更后的预览关闭。新增 `submission-key.spec.ts` 两项，通过实际 API 创建任务，仅将前两次 HTTP 响应替换为测试失败，验证相同任务重试复用键，以及新版本和新文件独立生成键。HTTP 替身只存在于测试代码。

上述七项及既有频带元信息测试共八项通过，31.8 秒。最新 typecheck、lint、build 均通过。OpenAPI 类型由独立锁定环境重新生成，共 17 类，包含绑定版本编码字段。修改范围为前端与本报告，模型与科学定义保持既有契约。
